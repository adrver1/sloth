## Bake pipeline (bake_all.py, bake_camp_lightmap.py, bake_ground.py, export_casters.cjs)

The bake pipeline is four steps driven by props/bake_all.py (83 lines): (1) layout: starts python http.server on :8765, node props/shadow/export_casters.cjs drives headless Chromium (SwiftShader) through the whole camp page and writes props/shadow/layout_picked.json (plus a casters_*.glb nothing reads); (2) light: Blender runs props/camp/bake_camp_lightmap.py, which exec()s the three lived builders (each does a factory reset, rebuilds, re-renders 7 textures incl. 3 Cycles CPU renders of the wood stack, and overwrites props/lived/*.glb), factory-resets again, builds the picked set (13 objects, 9 discarded), re-imports the lived GLBs, unwraps one shared atlas, then makes 16 bpy.ops.object.bake calls at 512 samples with adaptive sampling off (11 at 4096: AO, sun, sun-open, 4 light groups + 4 back-face passes for two thin cards; 5 ground passes at 1024), writes camp_lm_{4k,2k,1k}.png and camp_lm_sun_* (2k/1k are box-downsampled from the 4k, not re-baked), two ground PNGs, camp_lights.json, four GLBs and their base64 .txt; (3) ktx: toktx re-encodes five PNGs to .ktx2.txt and flips a flag in camp_lights.json; (4) ground: props/ground/bake_ground.py (numpy/PIL) writes the soil JPG and mask. Nothing is stamped or hashed: every run redoes everything in its step, and nobody can tell from the repo whether committed bakes match the committed generators (the jeep GLB and the bake script both changed after the last light bake). **Status: fixed** in [d17235f](https://github.com/adrver1/sloth/commit/d17235f), [b700bf0](https://github.com/adrver1/sloth/commit/b700bf0). Rebaked on the GPU in b700bf0, so the trunk now casts its baked shadow

### genbake-14 · high · M · duplicate
**About 25 layout and light constants are mirrored by hand between the bake and the page**

**Status: fixed** in [8250f6d](https://github.com/adrver1/sloth/commit/8250f6d), [1829576](https://github.com/adrver1/sloth/commit/1829576). Export_casters.cjs writes a place block from the live page and the bake reads it; the hand-typed copies are gone

Why: Every placement change needs a matching edit in a 442-line Blender script that cloud threads cannot run; a miss shows up only after a GPU rebake as light in the wrong place.

(3) Delete the Python copies and read the block; the same file can later carry the builders' numbers for the page (soup surface, laundry line), as camp_lights.json already does for the colours.

### genbake-18 · high · L · separation
**The light bake couples to the lived builders through exec, a monkey-patched bake and a GLB written to disk and read back**  _(rebake, restructure, changes behaviour)_

**Status: partly fixed** in [c473b25](https://github.com/adrver1/sloth/commit/c473b25). The bake calls each builder's make() directly: no exec, no patching. The GLB round trip stays (through a temporary folder) because the glTF export triangulates and splits vertices, and the atlas is built on that result

Where: `props/camp/bake_camp_lightmap.py:80-88`; `props/camp/bake_camp_lightmap.py:157-184`; `props/camp/bake_camp_lightmap.py:436-439`

Why: The order of side effects is the interface: a new builder, a rename or an import-style change breaks the bake in ways no one can test without Blender. The round trip is also why a failed run leaves committed GLBs half-made (genbake-04).

Fix: Give each builder a make(M=None) that returns its named objects in the current scene with no reset, bake or export, and keep build() as a thin wrapper for stand-alone previews writing to a temp path. The bake script then does: reset once, import the builders normally, call make() for each, flat_bake, place, unwrap, bake, export once. Drop the three densify patches and the build_lived import in build_fire.py.

Measured or estimate: Estimate: removes 3 of 4 factory resets, 3 GLB exports and 3 imports per run (a few seconds) and may raise atlas coverage; the coverage line the script prints should be compared before and after.

The fixed cost per Cycles session (genbake-24) is not affected, so the wall-clock gain is smaller; the per-pass times the script prints will show the split.

<a id="genbake-26"></a>
### genbake-26 · high · M · perf-generator
**No stamps: every run redoes its whole step, and the repo cannot say whether a committed bake is current**

**Status: open**

Where: `props/bake_all.py:51-83`; `props/camp/bake_camp_lightmap.py:83-88`; `props/lived/build_lived.py:741`

Why: Wasted GPU-thread time on unchanged inputs, binary churn in git, and no way for a cloud thread to know whether its change needs a rebake.

Fix: Step 1 of an incremental pipeline, inside bake_all.py only. Keep a committed props/bake.lock.json with, per step, a sha256 over its inputs and arguments and the sha256 of each output. Inputs: layout = the exporter and the page's layout sources; light = bake_camp_lightmap.py, build_camp.py, the three lived builders, jeep_<jeep>.glb, the deadwood (later also place) part of the layout JSON, size/samples/ground/angle/margin and the Blender version; ktx = each PNG plus the toktx flags; ground = bake_ground.py, its arguments and the layout JSON without deadwood and height. Write the layout with floats rounded to 4 decimals so hashes are stable across machines. A step runs only when its input hash differs or an output is missing or altered; --force runs all; --check prints the stale steps and exits 1, so any thread (and the publish check) can see 'light: stale, jeep_expedition.glb changed' without Blender. Do not rewrite a GLB or .txt whose content hash is unchanged.

Measured or estimate: Estimate: a run with nothing changed drops from a full bake to the layout step plus hashing (well under a minute); a ground-only change no longer touches Cycles.

## Generators: camp props and jeep (build_camp.py, build_jeep.py)

props/camp/build_camp.py (843 lines) and props/jeep/build_jeep.py (972 lines) work and are readable prop by prop, but both carry a lot that the live camp no longer uses, and they are tied to the other props scripts through monkey-patching instead of arguments. Static review only: nothing was run, so every time figure below is an estimate.

What runs today. props/bake_all.py -> bake_camp_lightmap.py imports build_camp and calls only reset(), picked(), apply_all(), BUDGET and STOVE; it swaps build_camp.bake for a flat-colour stand-in. build_camp's own AO bake, densify(), lean() and build() are reached only through the archive CLI (`build_camp.py --style ...`, which writes into props/camp/archive/). So densify() does subdivide purely for the AO bake and that inflated geometry is exported, but only for archived styles; the live GLB (camp_picked_lm.glb) is not densified, and the BUDGET decimate never triggers there. build_jeep.py is not part of bake_all at all: the jeep GLB is built by hand, its page .txt copy is made by hand, and the light bake just imports whatever GLB is on disk.

Main themes. (1) Wasted building: picked() builds the full rustic and jungle sets (12 objects) and deletes 9 of them; about three quarters of its roughly 900 Blender operator calls go to deleted parts. (2) Operator-heavy helpers: every primitive costs at least three bpy.ops calls (add, select_all, transform_apply), join() costs 2n+3, and build_jeep's outward() enters and leaves edit mode 28 times; a jeep build is about 1,100 to 1,300 operator calls and 19 EXACT booleans.
